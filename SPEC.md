# Спецификация ai-challenge

Документ описывает текущее состояние проекта. Обновляется при каждом коммите (см. раздел [История изменений](#10-история-изменений)).

## 1. Обзор

Чат-приложение для общения с [DeepSeek API](https://api-docs.deepseek.com/).

| Параметр | Значение |
|---|---|
| Название | Помогатор2К |
| Назначение | Веб-чат с моделью `deepseek-chat` с потоковым выводом ответов |
| Клиент | Статическая HTML-страница (vanilla JS + CSS) |
| Сервер | Node.js, встроенный `http` + `fetch`, без сторонних зависимостей |
| Формат ответов | SSE (Server-Sent Events), текст приходит постепенно |
| Язык интерфейса | Русский |

## 2. Архитектура

```
Браузер ──POST /api/chat {messages, model}──> Node-сервер ──stream:true──> DeepSeek  / OpenCode Go
Браузер <────SSE-чанки (data: {...})──── Node-сервер <────SSE-чанки────  апстрим (выбор по model)
```

- Браузер общается только с локальным сервером; API-ключи в клиент не попадают.
- Сервер проксирует запрос в целевой апстрим и пересылает SSE-поток клиенту как есть. Апстрим выбирается по префиксу `model`: `opencode/…` → OpenCode Go (`/zen/go/v1/chat/completions`), иначе → DeepSeek (`/chat/completions`).
- Клиент парсит чанки и постепенно выводит `delta.content`.

## 3. Сервер (`server.js`)

### 3.1. `GET /*` — статика

- Раздаёт файлы из `public/`; `/` → `public/index.html`.
- Поддерживаемые MIME: `.html`, `.css`, `.js`, `.json`, `.png`, `.jpg`, `.svg`, `.ico`; прочее — `application/octet-stream`.
- Защита от path traversal: путь после `path.normalize` обязан начинаться с `PUBLIC_DIR`, иначе `403`.
- Ошибки: `404 Not found` (файл отсутствует), `405 Method not allowed` (не GET/POST).

### 3.2. `POST /api/chat` — прокси в выбранный апстрим

**Запрос:** `Content-Type: application/json`

```json
{ "model": "opencode/glm-5.3", "messages": [ { "role": "user", "content": "текст" } ] }
```

- `messages` — массив в формате OpenAI (роль + содержание). Лимит тела — 1 МБ.
- `model` — необязательная строка: модель запроса. Префикс `opencode/` маршрутизирует запрос в OpenCode (префикс срезается, ключ — `OPENCODE_API_KEY`), иначе — в DeepSeek (`model` как есть, ключ — `DEEPSEEK_API_KEY`). Отсутствует/некорректна — используется `deepseek-chat` по умолчанию.
- OpenCode-модель (после префикса) валидируется регуляркой `[a-z0-9][a-z0-9._-]*` и должна входить в белый список `GO_CHAT_MODELS` (модели подписки Go, `/zen/go/v1/chat/completions`) или `ZEN_FREE_MODELS` (бесплатные модели Zen, `/zen/v1/chat/completions`); иначе `400`.
- Необязательные параметры генерации (невалидные значения молча игнорируются, запрос не отклоняется): `temperature` (число 0–2), `top_p` (число 0–1; `0` нормализуется в `0.01`, т.к. допустимый диапазон DeepSeek — `(0, 1.0]`), `max_tokens` (положительное целое), `stop` (массив непустых строк, до 16 элементов), `response_format` (`{"type":"json_object"}`).

**Ответ (успех):** `200`, `Content-Type: text/event-stream; charset=utf-8`, тело — SSE-поток, пересылаемый из апстрима без преобразований. Финальный чанк перед `data: [DONE]` содержит объект `usage` (токены запроса) — сервер запрашивает его через `stream_options.include_usage`.

**Ошибки (JSON `{ "error": "..." }`):**

| Код | Причина |
|---|---|
| 400 | Тело — невалидный JSON, `messages` — пустой массив / не массив, либо `opencode/…`-модель не поддержана |
| 401, 402, 429, … | Код и статус ошибки апстрима (DeepSeek / OpenCode) проксируется как есть; в `error` добавляется человекочитаемое сообщение апстрима (например, `Insufficient balance`) |
| 500 | Не задан соответствующий ключ (`DEEPSEEK_API_KEY` / `OPENCODE_API_KEY`) либо внутренняя ошибка сервера |

Отключение клиента (`req.close`) разрывает upstream-поток (`stream.destroy()`).

### 3.3. `GET /api/models` — список доступных моделей

Агрегирует модели всех настроенных апстримов и возвращает `200`, `{"object":"list","data":[{"id":"…","owned_by":"…"}]}`:

- DeepSeek (если задан `DEEPSEEK_API_KEY`): все модели из `GET https://api.deepseek.com/models`, `id` как есть, `owned_by: "deepseek"`.
- OpenCode Go (если задан `OPENCODE_API_KEY`): модели из `GET https://opencode.ai/zen/go/v1/models`, отфильтрованные по `GO_CHAT_MODELS`.
- OpenCode Zen — бесплатные (если задан `OPENCODE_API_KEY`): модели из `GET https://opencode.ai/zen/v1/models`, отфильтрованные по `ZEN_FREE_MODELS`.

Все OpenCode-модели — с префиксом `opencode/`, `owned_by: "opencode"`.

Ошибки: `500` (не задан ни один ключ), `502` (не удалось получить модели ни из одного доступного апстрима). Отказ одного апстрима не роняет весь список — отдаются модели оставшихся (с предупреждением в лог).

## 4. Интеграция апстримов

### 4.1. DeepSeek

| Параметр | Значение |
|---|---|
| Endpoint | `https://api.deepseek.com/chat/completions` |
| Модель | передаётся клиентом в `model` (по умолчанию `deepseek-chat`); список доступных — `GET /api/models` |
| Режим | `stream: true` |
| stream_options | `{ "include_usage": true }` — финальный чанк стрима содержит `usage` (prompt/completion/total tokens) |
| Параметры генерации | `temperature`, `top_p`, `max_tokens`, `stop`, `response_format` — опционально прокидываются из запроса клиента после серверной валидации |
| Авторизация | `Authorization: Bearer $DEEPSEEK_API_KEY` |

Поток — OpenAI-совместимый SSE: строки `data: {"choices":[{"delta":{"content":"..."}}]}` и терминатор `data: [DONE]`. У reasoning-моделей в `delta` дополнительно приходит `reasoning_content` (промежуточные рассуждения перед финальным ответом).

Детерминизм не гарантируется даже при `temperature=0` и `top_p=0.01` (MoE-маршрутизация, недетерминизм плавающей точки на GPU, серверный батчинг). Экспериментальные данные: `deepseek-chat` — ~2/3 совпадений, `deepseek-reasoner` — 0/3; `seed` принимается, но воспроизводимость не обеспечивает.

Технический нюанс: тело ответа `fetch()` — web `ReadableStream` (без `.pipe()`); для передачи в Node-ответ используется `Readable.fromWeb()`.

### 4.2. OpenCode Go (подписка $10/мес)

| Параметр | Значение |
|---|---|
| Endpoint | `https://opencode.ai/zen/go/v1/chat/completions` (OpenAI-совместимый) |
| Каталог | `https://opencode.ai/zen/go/v1/models` → `{"object":"list","data":[{"id":"…","owned_by":"opencode"}]}` |
| Модель | передаётся клиентом с префиксом `opencode/` (например `opencode/glm-5.3`); сервер срезает префикс и проверяет по белому списку `GO_CHAT_MODELS` |
| Режим | `stream: true` |
| stream_options | `{ "include_usage": true }` |
| Параметры генерации | те же (`temperature` 0–2, `top_p`, `max_tokens`, `stop`, `response_format`) |
| Авторизация | `Authorization: Bearer $OPENCODE_API_KEY` |
| Доп. заголовки | `x-opencode-session: <UUID>` (сессия сервера) + `User-Agent: pomogator2k/1.0` — по рекомендации OpenCode против злоупотреблений |

Подписка Go — $10/мес с лимитами использования ($12 за 5 ч, $30 в неделю, $60 в месяц); при превышении лимита модели блокируются (можно включить fallback на Zen-баланс). Поддерживаются только модели белого списка `GO_CHAT_MODELS` — те, что отдаются через `/zen/go/v1/chat/completions` (16 шт.: GLM 5.x, Kimi K2.6/K2.7/K3, LongCat-2.0, DeepSeek V4, MiMo-V2.5/-Pro, Hy3/Hy4, Omen Alpha). Модели MiniMax/Qwen (Anthropic-протокол `/v1/messages`) и GPT/Grok/Muse Spark (Responses-протокол `/v1/responses`) не включены. Формат SSE такой же, как у DeepSeek (`choices[].delta.content`, у reasoning-моделей — `reasoning_content`).

### 4.3. OpenCode Zen — бесплатные модели

| Параметр | Значение |
|---|---|
| Endpoint | `https://opencode.ai/zen/v1/chat/completions` (OpenAI-совместимый) |
| Каталог | `https://opencode.ai/zen/v1/models` |
| Модели | `ZEN_FREE_MODELS`: `big-pickle`, `deepseek-v4-flash-free`, `mimo-v2.5-free`, `ling-3.0-flash-fin-free`, `nemotron-3-ultra-free`, `nemotron-3.5-lightning-free` |
| Авторизация | `Authorization: Bearer $OPENCODE_API_KEY` (тот же ключ Go) |

Бесплатные модели Zen доступны и держателям подписки Go (по доке Go: при исчерпании лимитов подписки бесплатные модели продолжают работать). Они не тарифицируются и не требуют баланса; маршрутизируются в `/zen/v1/chat/completions`, в дропдауне помечены зелёным («free») и отображаются внизу группы. Модели `muse-spark-*-contributor-free` исключены (Responses-протокол).

## 5. Клиент (`public/`)

### 5.1. Компоненты

- `index.html` — окно приложения `.app`: слева панель вкладок чатов `.tabs` (20%), по центру чат `.chat` (60%), справа панель настроек `.settings` (20%, min-width 230px); под окном — футер «Сожжено токенов: N».
- Панель вкладок: список вкладок (название + крестик «×»), а внизу списка — ряд кнопок: квадратная `[+]` «Новый чат» и «Подвести Итоги».
- Панель настроек: визуальный блок `.settings__brand` — заголовок «Помогатор2К» + кастомный дропдаун выбора модели `.dropdown` (#model-button + всплывающая панель `#model-menu`); ниже форма настроек генерации: «Температура» (слайдер 0–2, шаг 0.1, default 1), «top_p» (слайдер 0–1, шаг 0.01, default 1), «Лимит токенов» (числовой инпут), «Стоп слова» (текстовый инпут), «Режим ответа» (тумблер). Шапки у чата нет.
- `style.css` — тёмная тема; сообщения: пользователь — справа, ассистент — слева; свечение окна приложения.
- `app.js` — логика чатов (вкладки), блоки «вопрос+ответ» со строкой статистики, счётчик токенов.

### 5.2. Поведение

- Выбор модели: кастомный дропдаун `.dropdown` в панели настроек (в одном визуальном блоке с заголовком приложения) — кнопка с цветной точкой выбранной модели и всплывающая панель. Панель заполняется из `GET /api/models` при загрузке; модели группируются по `owned_by` («DeepSeek» / «OpenCode Go»), внутри группы отсортированы по убыванию цены (сверху дорогие, внизу бесплатные), OpenCode-модели показаны чистым именем, а в `value` (и в `model` запроса) хранится полный id с префиксом `opencode/`. Каждая модель помечена цветной точкой по стоимости 1M output-токенов (статистическая карта `MODEL_PRICES`): зелёный — ≤$1 (включая бесплатные Zen-модели), жёлтый — ≤$4, красный — >$4; справа мелким текстом цена (`free` / `$X.XX/1M`); внизу панели — легенда «дешёвый / средний / дорогой». Модель вне карты — серая точка без цены. Выбранная модель — с галочкой ✓ и акцентным цветом. Открытие/закрытие: клик по кнопке, клик вне панели, `Esc`; выбор — клик по строке. Смена модели сбрасывает слайдеры `temperature`/`top_p` к дефолтам и применяется к последующим запросам любого чата (сервер маршрутизирует по префиксу). При недоступности `/api/models` — fallback-список `deepseek-v4-flash` / `deepseek-v4-pro`.
- Вкладки чатов: несколько чатов в памяти страницы (без localStorage). `[+]` создаёт вкладку «Новый чат»; первый отправленный вопрос переименовывает вкладку в текст вопроса (переносы строк → пробелы); длинное название обрезается троеточием. Переключение вкладок меняет отображаемый чат (у каждого чата свой DOM-контейнер ленты, состояние сохраняется целиком: «Размышления», блоки вопрос+ответ, JSON-конверты, скролл). Крестик «×» закрывает вкладку после `confirm`; при закрытии активной вкладки активной становится соседняя (предыдущая, иначе следующая); закрытие последней вкладки создаёт новую пустую. Всегда есть минимум одна вкладка; при старте — одна «Новый чат».
- «Подвести итоги»: постоянный чат с фиксированным названием «Подвести итоги». Кнопка с таким же названием открывает/активирует этот чат (создаёт при первом нажатии, не очищает при повторных). При создании отображается приветственное сообщение «Задайте вопрос с контекстом всех открытых чатов». Пользователь может задавать вопросы, а модель получает в `messages` текущую историю этого чата плюс системный контекст с полным содержимым всех остальных открытых чатов (кроме самого чата итогов); после каждого ответа в контексте идёт строка статистики `[модель: … | время: …, вход: …, выход: …, рассужд.: …, цена: …]`, так что можно попросить сформировать отчёт по чатам (суммы/средние времени, токенов и стоимости). Follow-up вопросы работают в рамках чата итогов. Запросы стримятся через общий конвейер.
- Раскладка: вкладки 20% | чат 60% | настройки 20%; панели вкладок и настроек скроллятся при переполнении. На экранах <700px панель вкладок уходит наверх (до 35% высоты, скролл), настройки — вниз (до 45%), чат — по центру.
- Если модель стримит `reasoning_content` (reasoning-модели), рассуждения скрыты под сворачиваемой меткой «Размышление» (нативный `<details>`/`<summary>`): блок свёрнут по умолчанию, раскрывается кликом по метке; во время «размышления» рядом с меткой показывается спиннер (снимается при старте финального ответа или по завершении стрима).
- Настройки генерации (панель справа, глобальны для всех чатов): «Температура» → `temperature` (слайдер 0–2, шаг 0.1, default 1); «top_p» → `top_p` (слайдер 0–1, шаг 0.01, default 1; значение 0 перед отправкой нормализуется в 0.01, т.к. DeepSeek не принимает 0); «Лимит токенов» → `max_tokens` (пусто — не отправляется); «Стоп слова» — список через запятую → `stop` (пусто — не отправляется). При смене модели слайдеры `temperature`/`top_p` сбрасываются к дефолтам.
- «Режим ответа» (тумблер, по умолчанию вкл. — обычный режим): в выключенном положении включается JSON-режим — в запрос добавляются `response_format: {"type":"json_object"}` и первым сообщением в `messages` системный промпт «Выдавай ответ строго в формате JSON.» (добавляется в копию истории, UI-история не переписывается; смена тумблера действует на последующие запросы).
- JSON-режим, рендер: ответ отображается моноширинным `<pre class="message__json">` как `JSON.stringify({thinking, response, date, tokens}, null, 2)`, объект дополняется по мере стрима: `thinking` — накопленный `reasoning_content`, `response` — накопленный контент, `date` — ISO 8601 на момент отправки, `tokens` — `completion_tokens` из `usage` (0 до завершения). Спиннер и свёрнутый блок «Размышление» работают как в обычном режиме; строка статистики блока отображается под конвертом.
- Футер «Сожжено токенов: N» всегда виден под окном приложения; N — сумма `total_tokens` всех запросов за сессию (по всем чатам; история переписки тарифицируется повторно при каждом запросе — как в биллинге API); стартовое значение 0.
- Блок «вопрос + ответ»: каждая пара «сообщение пользователя → ответ модели» обёрнута в один визуальный блок `.qa` (рамка, скругление, лёгкий фон); внутри — баблы пользователя (справа) и ассистента (слева, со всем текущим: «Размышление», JSON-конверт, ошибки). Внизу блока — строка статистики `.qa__stats` в одну строку через запятую: `время: 2.33s, вход: 202, выход: 233, рассужд.: 400, цена: 0.0000002`. Поля: время — от старта запроса до конца стрима, `(сек).toFixed(2)` + `s`; вход — `usage.prompt_tokens`; выход — `usage.completion_tokens` (все output-токены); рассужд. — `usage.completion_tokens_details.reasoning_tokens` (если апстрим не отдаёт — `–`); цена — `(вход×цена_in + выход×цена_out)/1e6` по карте `MODEL_PRICES` (формат числа без хвостовых нулей, у бесплатных `0`). При отсутствии данных — прочерк `–` в соответствующем поле (время показывается всегда, в т.ч. при ошибке).
- Старые подсказки «токенов: N» под сообщениями удалены (их заменила строка статистики в блоке). Автономные сообщения (приветствие, локальные подсказки) — без блока и статистики.
- Приветственное сообщение «Привет! Чем могу помочь?» при создании нового чата.
- Отправка: кнопка или `Enter`; `Shift+Enter` — перенос строки; кнопка блокируется только в чате, ожидающем ответа (`chat.busy`). Переключение на другой чат сразу меняет состояние кнопки: в незанятом чате можно отправлять сообщения независимо от активных запросов в других чатах. В каждом чате одновременно выполняется не более одного запроса; стрим продолжает писаться в контейнер своего чата в фоне даже при переключении вкладок.
- Ответ ассистента стримится в bubble по левому краю (заготовка «...» без центрирования — класс `message--empty` снимается при первом тексте).
- Поле ввода: авторесайз по содержимому, максимум **2 строки**; при превышении — вертикальный скролл (`overflow-y: auto`), в незаполненном поле полосы нет (`overflow-y: hidden`).
- История каждого диалога хранится в памяти страницы (в состоянии соответствующего чата) и целиком передаётся в `messages` этого чата (контекст многораундового диалога). При ошибке ответа последнее пользовательское сообщение откатывается из истории чата.
- Ошибки показываются в bubble вида «Ошибка: …»; пустой ответ — «(пустой ответ)», кроме случая, когда пустой ответ вызван лимитом токенов (`finish_reason = "length"`) — тогда показывается «<LLM уперлась в ограничение по токенам: N>», где N — значение «Лимита токенов» из настроек (если не задан — фактическое число из `usage.completion_tokens`). Непустой обрезанный ответ отображается как есть.
- Оформление: градиентный фон страницы, glow-рамка и скругление окна приложения (`box-shadow`), градиентный заголовок «Помогатор2К» со свечением (`drop-shadow`), свечение кнопки при hover и поля при фокусе.
- Скроллбары ленты чата и тела рассуждений — кастомные, тонкие (8px / 6px), в стиле проекта (акцентный цвет `rgba(79,140,255,.45)`, hover `.7`, прозрачный track), включая Firefox (`scrollbar-width: thin` + `scrollbar-color`).

## 6. Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | нет* | — | Ключ DeepSeek API (только на сервере) |
| `OPENCODE_API_KEY` | нет* | — | Ключ подписки OpenCode Go ($10/мес; opencode.ai/auth/zen) — доступ к моделям OpenCode Go (только на сервере) |
| `PORT` | нет | `3000` | Порт HTTP-сервера |

`*` — достаточно задать хотя бы один из API-ключей; подключённый ключ активирует соответствующий провайдер (модели и маршрутизацию).

Загрузка — через `node --env-file=.env`. Пример — в `.env.example`.

## 7. Требования

- Node.js **20.6+** (поддержка `--env-file` и глобального `fetch`).
- Сторонние npm-зависимости — отсутствуют.

## 8. Безопасность

- API-ключи хранятся только на сервере (`DEEPSEEK_API_KEY` / `OPENCODE_API_KEY` из env), в браузер не отдаются.
- `.env` в `.gitignore` (в репозиторий не попадает).
- Path traversal в статике блокируется проверкой префикса пути.
- Лимит размера тела запроса — 1 МБ.
