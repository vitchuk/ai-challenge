# Спецификация ai-challenge

Документ описывает текущее состояние проекта. Обновляется при каждом коммите (см. раздел [История изменений](#10-история-изменений)).

## 1. Обзор

Чат-приложение для общения с [DeepSeek API](https://api-docs.deepseek.com/).

| Параметр | Значение |
|---|---|
| Название | Помогатор2К |
| Назначение | Веб-чат с моделью `deepseek-chat` с потоковым выводом ответов |
| Клиент | Статическая HTML-страница (vanilla JS + CSS) |
| Сервер | Node.js, встроенный `http` + `fetch`, без сторонних зависимостей |
| Формат ответов | SSE (Server-Sent Events), текст приходит постепенно |
| Язык интерфейса | Русский |

## 2. Архитектура

```
Браузер ──POST /api/chat {messages}──> Node-сервер ──stream:true──> https://api.deepseek.com/chat/completions
Браузер <────SSE-чанки (data: {...})──── Node-сервер <────SSE-чанки──── DeepSeek
```

- Браузер общается только с локальным сервером; API-ключ в клиент не попадает.
- Сервер проксирует запрос в DeepSeek и пересылает SSE-поток клиенту как есть.
- Клиент парсит чанки и постепенно выводит `delta.content`.

## 3. Сервер (`server.js`)

### 3.1. `GET /*` — статика

- Раздаёт файлы из `public/`; `/` → `public/index.html`.
- Поддерживаемые MIME: `.html`, `.css`, `.js`, `.json`, `.png`, `.jpg`, `.svg`, `.ico`; прочее — `application/octet-stream`.
- Защита от path traversal: путь после `path.normalize` обязан начинаться с `PUBLIC_DIR`, иначе `403`.
- Ошибки: `404 Not found` (файл отсутствует), `405 Method not allowed` (не GET/POST).

### 3.2. `POST /api/chat` — прокси в DeepSeek

**Запрос:** `Content-Type: application/json`

```json
{ "model": "deepseek-v4-flash", "messages": [ { "role": "user", "content": "текст" } ] }
```

- `messages` — массив в формате OpenAI (роль + содержание). Лимит тела — 1 МБ.
- `model` — необязательная строка: модель запроса. Валидируется регуляркой `[a-z0-9][a-z0-9._-]*`; отсутствует/некорректна — используется `deepseek-chat` по умолчанию.
- Необязательные параметры генерации (невалидные значения молча игнорируются, запрос не отклоняется): `temperature` (число 0–1), `top_p` (число 0–1; `0` нормализуется в `0.01`, т.к. допустимый диапазон DeepSeek — `(0, 1.0]`), `max_tokens` (положительное целое), `stop` (массив непустых строк, до 16 элементов), `response_format` (`{"type":"json_object"}`).

**Ответ (успех):** `200`, `Content-Type: text/event-stream; charset=utf-8`, тело — SSE-поток, пересылаемый из DeepSeek без преобразований. Финальный чанк перед `data: [DONE]` содержит объект `usage` (токены запроса) — сервер запрашивает его через `stream_options.include_usage`.

**Ошибки (JSON `{ "error": "..." }`):**

| Код | Причина |
|---|---|
| 400 | Тело — невалидный JSON или `messages` — пустой массив / не массив |
| 401, 402, 429, … | Код и статус ошибки DeepSeek проксируется как есть |
| 500 | Не задан `DEEPSEEK_API_KEY` либо внутренняя ошибка сервера |

Отключение клиента (`req.close`) разрывает upstream-поток (`stream.destroy()`).

### 3.3. `GET /api/models` — список доступных моделей

Проксирует `GET https://api.deepseek.com/models` и возвращает его JSON как есть (`200`, `{"data":[{"id":"..."}]}`). Ошибки: `500` (нет ключа), статус DeepSeek при его ошибке, `502` (DeepSeek недоступен).

## 4. Интеграция DeepSeek

| Параметр | Значение |
|---|---|
| Endpoint | `https://api.deepseek.com/chat/completions` |
| Модель | передаётся клиентом в `model` (по умолчанию `deepseek-chat`); список доступных — `GET /api/models` |
| Режим | `stream: true` |
| stream_options | `{ "include_usage": true }` — финальный чанк стрима содержит `usage` (prompt/completion/total tokens) |
| Параметры генерации | `temperature`, `top_p`, `max_tokens`, `stop`, `response_format` — опционально прокидываются из запроса клиента после серверной валидации |
| Авторизация | `Authorization: Bearer $DEEPSEEK_API_KEY` |

Поток — OpenAI-совместимый SSE: строки `data: {"choices":[{"delta":{"content":"..."}}]}` и терминатор `data: [DONE]`. У reasoning-моделей в `delta` дополнительно приходит `reasoning_content` (промежуточные рассуждения перед финальным ответом).

Детерминизм не гарантируется даже при `temperature=0` и `top_p=0.01` (MoE-маршрутизация, недетерминизм плавающей точки на GPU, серверный батчинг). Экспериментальные данные: `deepseek-chat` — ~2/3 совпадений, `deepseek-reasoner` — 0/3; `seed` принимается, но воспроизводимость не обеспечивает.

Технический нюанс: тело ответа `fetch()` — web `ReadableStream` (без `.pipe()`); для передачи в Node-ответ используется `Readable.fromWeb()`.

## 5. Клиент (`public/`)

### 5.1. Компоненты

- `index.html` — окно приложения `.app`: слева чат (80% ширины, в шапке — дропдаун выбора модели), справа панель настроек (20%, min-width 230px); под окном — футер «Сожжено токенов: N».
- Панель настроек: заголовок «Помогатор2К» сверху + форма настроек генерации: «Четкость ответа» (слайдер 0–100%), «Разнообразие ответов» (слайдер 0–100%), «Лимит токенов» (числовой инпут), «Стоп слова» (текстовый инпут), «Режим ответа» (тумблер).
- `style.css` — тёмная тема; сообщения: пользователь — справа, ассистент — слева; свечение окна приложения.
- `app.js` — логика чата, счётчики токенов.

### 5.2. Поведение

- Выбор модели: дропдаун в шапке чата; заполняется из `GET /api/models` при загрузке, при недоступности — fallback-список `deepseek-chat` / `deepseek-reasoner`. Смена модели применяется к последующим запросам; история диалога сохраняется и передаётся новой модели целиком.
- Если модель стримит `reasoning_content` (reasoning-модели), рассуждения скрыты под сворачиваемой меткой «Размышление» (нативный `<details>`/`<summary>`): блок свёрнут по умолчанию, раскрывается кликом по метке; во время «размышления» рядом с меткой показывается спиннер (снимается при старте финального ответа или по завершении стрима).
- Настройки генерации (панель справа) передаются в каждом запросе: «Четкость ответа» 0–100% → `temperature` 0.0–1.0 и «Разнообразие ответов» 1–100% → `top_p` 0.01–1.0 (слайдеры, визуально по умолчанию 100%); «Лимит токенов» → `max_tokens` (пусто — не отправляется); «Стоп слова» — список через запятую → `stop` (пусто — не отправляется). `temperature`/`top_p` отправляются только после того, как пользователь вручную изменил соответствующий слайдер — пока не тронут, параметры не передаются и модель использует свои серверные дефолты; при смене модели в дропдауне оба слайдера сбрасываются к 100% и снова не отправляются. Значения слайдеров отображаются рядом с названиями, настройки живут в сессии страницы.
- «Режим ответа» (тумблер, по умолчанию вкл. — обычный режим): в выключенном положении включается JSON-режим — в запрос добавляются `response_format: {"type":"json_object"}` и первым сообщением в `messages` системный промпт «Выдавай ответ строго в формате JSON.» (добавляется в копию истории, UI-история не переписывается; смена тумблера действует на последующие запросы).
- JSON-режим, рендер: ответ отображается моноширинным `<pre class="message__json">` как `JSON.stringify({thinking, response, date, tokens}, null, 2)`, объект дополняется по мере стрима: `thinking` — накопленный `reasoning_content`, `response` — накопленный контент, `date` — ISO 8601 на момент отправки, `tokens` — `completion_tokens` из `usage` (0 до завершения). Спиннер, свёрнутый блок «Размышление» и подсказка токенов работают как в обычном режиме.
- Раскладка: чат — 80% окна, панель настроек — 20% (скроллится при переполнении); на экранах <700px панель настроек переносится вниз (до 45% высоты, скролл).
- Футер «Сожжено токенов: N» всегда виден под окном приложения; N — сумма `total_tokens` всех запросов за сессию (история переписки тарифицируется повторно при каждом запросе — как в биллинге API); стартовое значение 0.
- В каждом сообщении пользователя и ответе ИИ — подсказка «токенов: N» (мелкий серый текст внизу блока сообщения): для ответа ИИ — `completion_tokens` (точно); для сообщения пользователя — арифметика по `usage` (прирост `prompt_tokens` между соседними запросами минус `completion_tokens` предыдущего и константа обвязки сообщения ~4 ток.). Подсказка появляется после завершения ответа.
- Приветственное сообщение и сообщения об ошибках — локальные, без подсказки токенов.
- Приветственное сообщение «Привет! Чем могу помочь?» при пустой ленте.
- Отправка: кнопка или `Enter`; `Shift+Enter` — перенос строки; кнопка блокируется до завершения ответа.
- Ответ ассистента стримится в bubble по левому краю (заготовка «...» без центрирования — класс `message--empty` снимается при первом тексте).
- Поле ввода: авторесайз по содержимому, максимум **2 строки**; при превышении — вертикальный скролл (`overflow-y: auto`), в незаполненном поле полосы нет (`overflow-y: hidden`).
- История диалога хранится в памяти страницы и целиком передаётся в `messages` (контекст многораундового диалога). При ошибке ответа последнее пользовательское сообщение откатывается из истории.
- Ошибки показываются в bubble вида «Ошибка: …»; пустой ответ — «(пустой ответ)», кроме случая, когда пустой ответ вызван лимитом токенов (`finish_reason = "length"`) — тогда показывается «<LLM уперлась в ограничение по токенам: N>», где N — значение «Лимита токенов» из настроек (если не задан — фактическое число из `usage.completion_tokens`). Непустой обрезанный ответ отображается как есть.
- Оформление: градиентный фон страницы, glow-рамка и скругление окна приложения (`box-shadow`), градиентный заголовок «Помогатор2К» со свечением (`drop-shadow`), свечение кнопки при hover и поля при фокусе.
- Скроллбары ленты чата и тела рассуждений — кастомные, тонкие (8px / 6px), в стиле проекта (акцентный цвет `rgba(79,140,255,.45)`, hover `.7`, прозрачный track), включая Firefox (`scrollbar-width: thin` + `scrollbar-color`).

## 6. Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | да | — | Ключ DeepSeek API (только на сервере) |
| `PORT` | нет | `3000` | Порт HTTP-сервера |

Загрузка — через `node --env-file=.env`. Пример — в `.env.example`.

## 7. Требования

- Node.js **20.6+** (поддержка `--env-file` и глобального `fetch`).
- Сторонние npm-зависимости — отсутствуют.

## 8. Безопасность

- API-ключ хранится только на сервере (`DEEPSEEK_API_KEY` из env), в браузер не отдаётся.
- `.env` в `.gitignore` (в репозиторий не попадает).
- Path traversal в статике блокируется проверкой префикса пути.
- Лимит размера тела запроса — 1 МБ.

## 9. Структура файлов

```
ai-challenge/
├── server.js          # HTTP-сервер: статика + POST /api/chat (SSE-прокси в DeepSeek)
├── public/
│   ├── index.html     # разметка чата
│   ├── style.css      # стили (тёмная тема)
│   └── app.js         # отправка, парсинг SSE, UI-поведение
├── .env.example       # пример конфигурации
├── .gitignore         # node_modules, .env
├── package.json       # npm start → node --env-file=.env server.js
├── AGENTS.md          # регламент для агента (обновление SPEC.md)
├── SPEC.md            # этот документ
└── README.md          # инструкция по установке и запуску
```
