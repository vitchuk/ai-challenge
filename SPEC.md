# Спецификация ai-challenge

Документ описывает текущее состояние проекта. Обновляется при каждом коммите (см. раздел [История изменений](#10-история-изменений)).

## 1. Обзор

Чат-приложение для общения с [DeepSeek API](https://api-docs.deepseek.com/) и [OpenCode](https://opencode.ai/) (подписка Go + бесплатные Zen-модели).

| Параметр | Значение |
|---|---|
| Название | Помогатор2К |
| Назначение | Веб-чат с LLM с потоковым выводом, мультичатами, командами |
| Клиент | Статическая HTML-страница (vanilla JS + CSS) |
| Сервер | Python 3.10+, FastAPI + uvicorn, httpx |
| Формат ответов | SSE (Server-Sent Events); текст ответа приходит целиком в финальном событии `done`, пофрагментная стриминг-выдача клиенту не используется |
| Сериализация структ. данных в промптах | TOON (Token-Oriented Object Notation) |
| Язык интерфейса | Русский |

## 2. Архитектура

```
Браузер ──HTTP/JSON + SSE──> API-слой (FastAPI) ──> Сервисный слой ──> Провайдеры ──JSON/SSE──> DeepSeek / OpenCode
                             тонкие маршруты,        ChatService,       роутинг по model,
                             валидация, статика      SessionRegistry    white-list'ы, ключи
```

- Браузер общается только с локальным сервером; API-ключи в клиент не попадают.
- Сервер хранит сессии-чаты в памяти и проксирует запросы в апстрим, пересылая клиенту **нормализованные** SSE-события (а не сквозные чанки апстрима).
- Апстрим выбирается по модели: `opencode/…` → OpenCode, иначе → DeepSeek.

### 2.1. Мультиагентная архитектура (задел)

`ChatService` уже выступает как «агент»: роль (системный промпт) + свои настройки генерации (temperature, top_p, **top_k**, max_tokens, stop) + модель + история с метаданными; он не зависит от HTTP и UI. В будущем планируется оркестратор (агент-модератор), который будет передавать контроль субагентам по очереди, вкладывая друг другу состояние через TOON-контекст (`ChatService.to_toon_context()`). В текущей итерации оркестратор не реализован — заложен только фундамент (независимые сервисы-агенты + реестр + TOON-контекст), поэтому следующий слой не потребует редизайна.

## 3. Сервер (`server/`)

### 3.1. Приложение и запуск

- `server/main.py:create_app()` собирает FastAPI-приложение: маршруты сессий и моделей + раздача статики из `public/` (StaticFiles, html=True).
- Lifespan приложения создаёт общий `httpx.AsyncClient`, реестр сессий `SessionRegistry` и запускает фоновую TTL-очистку осиротевших сессий.
- Запуск: `python -m server.main` (читает `PORT` из `.env`/окружения) или `uvicorn server.main:app`.
- Автодокументация HTTP API: `/docs` (OpenAPI).

### 3.2. `POST /api/sessions` — создать сессию

**Запрос:**

```json
{ "model": "opencode/glm-5.3", "settings": {"temperature": 0.1, "top_p": 0.01}, "system_prompt": "…", "kind": "chat" }
```

- `model` — необязательная модель по умолчанию (может переопределяться на запрос).
- `settings` — необязательные параметры генерации (валидируются, см. §3.5).
- `system_prompt` — необязательный системный промпт.
- `kind` — тип сессии: `chat` (по умолчанию), `summary` (чат «Итоги», контекст строится сервером), `ephemeral` (изолированный чат команды `/optimize-prompt`).

**Ответ:** `201`, `{"id": "chat-N", "model": …}`.

### 3.3. `POST /api/sessions/{id}/messages` — отправить сообщение (SSE)

**Запрос:**

```json
{ "content": "текст", "model": "…", "settings": {…}, "system_prompt": "…" }
```

- `content` — текст сообщения (обязателен). Сервер дописывает его в историю сессии.
- `model` / `settings` — необязательные переопределения для данного запроса (позволяют глобальной панели настроек действовать на все чаты).
- `system_prompt` — необязательный дополнительный системный промпт, вставляемый перед остальными (используется JSON-режимом клиента).

**Ответ (успех):** `200`, `text/event-stream`. Сервер стримит нормализованные события:

```
data: {"type":"session","id":"chat-N"}
data: {"type":"reasoning_start"}                       # начало раздумий (вейтер)
data: {"type":"reasoning_end","content":"…"}           # конец раздумий: полный текст
data: {"type":"done","content":"…","meta":{…}}         # завершение: весь текст + метаданные
data: {"type":"error","error":"…"}                     # ошибка (user-сообщение откатывается)
```

Текст ответа **не стримится пофрагментно** — `delta`-события клиенту не отправляются. Пока модель генерирует ответ (и раздумывает), клиент показывает **вейтер** (спиннер); весь текст приходит целиком в `content` финального события `done`.

Рассуждения (reasoning) передаются **двумя событиями**: `reasoning_start` — момент начала раздумий (клиент показывает спиннер на метке «Размышление»), и `reasoning_end` — завершение раздумий с **полным** накопленным текстом (`content`). После `reasoning_end` вейтер остаётся до `done` — ответ появляется сразу целиком.

`meta` содержит: `model`, `time_s`, `prompt_tokens`, `completion_tokens`, `reasoning_tokens`, `cost_usd`, `finish_reason`. Счётчики токенов берутся из `meta` (отдельного `usage`-события клиенту не шлётся).

**Ошибки (JSON `{"error": "…"}`):**

| Код | Причина |
|---|---|
| 404 | Сессия не найдена |
| 409 | Сессия занята (в этом чате уже идёт запрос) |
| 400 | `opencode/…`-модель не поддержана |
| 422 | Некорректное тело (например, пустой `content`) |
| 500 | Не задан нужный API-ключ |
| 401/402/429/… | Код и сообщение ошибки апстрима (проксируется) |

### 3.4. `GET /api/sessions/{id}` и `DELETE /api/sessions/{id}`

- `GET` — полное состояние сессии: `{id, kind, model, system_prompt, history: [{role, content, meta}]}`.
- `DELETE` — удаляет сессию из памяти сервера. `204` при успехе, `404` если сессии нет.

### 3.5. `GET /api/models` — список моделей с ценами

Агрегирует модели всех настроенных провайдеров и возвращает `{"object":"list","data":[{"id","owned_by","price"}]}`, где `price` — цена за 1M выходных токенов (для маркировки в UI; `0` — бесплатные, `null` — вне карты цен).

- DeepSeek (если задан `DEEPSEEK_API_KEY`): все модели из `GET https://api.deepseek.com/models`, `owned_by: "deepseek"`.
- OpenCode Go (если задан `OPENCODE_API_KEY`): модели из `/zen/go/v1/models`, отфильтрованные по `GO_CHAT_MODELS`.
- OpenCode Zen — бесплатные: модели из `/zen/v1/models`, отфильтрованные по `ZEN_FREE_MODELS`.

Все OpenCode-модели — с префиксом `opencode/`, `owned_by: "opencode"`.

Ошибки: `500` (не задан ни один ключ), `502` (не удалось получить модели ни из одного апстрима). Отказ одного апстрима не роняет весь список.

### 3.6. Валидация параметров генерации (`GenerationSettings`)

Перенесено из прежней Node-версии; невалидные значения молча игнорируются:

- `temperature` — число 0–2.
- `top_p` — число 0–1; `0` нормализуется в `0.01` (диапазон DeepSeek — `(0, 1.0]`).
- `top_k` — положительное целое. **Хранится** в настройках для будущих провайдеров, но в DeepSeek/OpenCode **не передаётся** (их API его не поддерживают).
- `max_tokens` — положительное целое.
- `stop` — массив непустых строк, до 16 элементов.
- `response_format` — `{"type":"json_object"}`.

### 3.7. Реестр сессий (`SessionRegistry`)

- `create/get/delete/list` — управление живыми сессиями; идентификаторы вида `chat-N` уникальны.
- `build_summary_context(exclude_id)` — собирает содержимое всех остальных сессий (история + метаданные) и сериализует его в **TOON**.
- Чат «Итоги» (`kind=summary`): при каждом запросе системный промпт пересобирается — `SUMMARY_CONTEXT_PROMPT` + TOON-контекст всех остальных сессий (follow-up вопросы работают).
- Фоновая TTL-очистка осиротевших сессий (после перезагрузки страницы, когда клиент не вызвал DELETE); период — `SESSION_TTL_HOURS` (по умолчанию 12 ч).

## 4. Интеграция апстримов

### 4.1. DeepSeek

| Параметр | Значение |
|---|---|
| Endpoint | `https://api.deepseek.com/chat/completions` |
| Модель | из запроса (по умолчанию `deepseek-chat`); список — `GET /api/models` |
| Режим | `stream: true`, `stream_options.include_usage: true` |
| Авторизация | `Authorization: Bearer $DEEPSEEK_API_KEY` |
| Идентичность | первым системным сообщением добавляется `DEEPSEEK_IDENTITY_PROMPT` — фиксирует модель как DeepSeek (модели DeepSeek V4 ошибочно представляются «ассистентом OpenAI» из-за особенностей обучения) |

### 4.2. OpenCode Go (подписка $10/мес)

| Параметр | Значение |
|---|---|
| Endpoint | `https://opencode.ai/zen/go/v1/chat/completions` |
| Модели | белый список `GO_CHAT_MODELS` (16 шт.) |
| Авторизация | `Authorization: Bearer $OPENCODE_API_KEY` |
| Доп. заголовки | `x-opencode-session: <UUID>` + `User-Agent: pomogator2k/2.0` |

### 4.3. OpenCode Zen — бесплатные модели

| Параметр | Значение |
|---|---|
| Endpoint | `https://opencode.ai/zen/v1/chat/completions` |
| Модели | `ZEN_FREE_MODELS` (6 шт.), маршрутизируются в `/zen/v1` |
| Авторизация | `Authorization: Bearer $OPENCODE_API_KEY` |

Провайдеры используют общий движок `providers/engine.py`, который разбирает OpenAI-совместимый SSE апстрима (`delta.content`, `delta.reasoning_content`, `usage`, `finish_reason`) и нормализует его в события `ChatEvent`. Ошибки апстрима проксируются с человекочитаемым сообщением.

## 5. Клиент (`public/`)

### 5.1. Компоненты

- `index.html` — окно приложения `.app`: слева панель вкладок чатов `.tabs` (20%), по центру чат `.chat` (60%), справа панель настроек `.settings` (20%); под окном — футер «Сожжено токенов: N». Дополнительно: дропдаун команд над полем ввода и модальное окно команды `/optimize-prompt`.
- `style.css` — тёмная тема; стили сообщений, вкладок, дропдауна моделей, дропдауна команд, модального окна.
- `app.js` — логика: серверные сессии-чаты, стрим SSE, команды, модалка, консольное логирование.

### 5.2. Серверные сессии

- Каждая чат-вкладка соответствует серверной сессии: при создании вкладки вызывается `POST /api/sessions`, `chat.sid` сохраняется в состоянии чата.
- Отправка сообщения — `POST /api/sessions/{sid}/messages` с `{content, model, settings, system_prompt}`; ответ парсится как нормализованные SSE-события.
- Закрытие вкладки (крестик «×», после `confirm`) вызывает `DELETE /api/sessions/{sid}` — серверная история удаляется.
- Чат «Подвести итоги» (`kind=summary`) создаётся по кнопке; контекст собирается сервером в TOON.

### 5.3. Поведение

- Выбор модели: кастомный дропдаун `.dropdown`; панель заполняется из `GET /api/models` (с ценами), группировка по `owned_by`, сортировка по цене, цветная маркировка + легенда. Смена модели сбрасывает слайдеры температуры/top_p к дефолтам.
- Вкладки чатов: несколько чатов в памяти страницы (без localStorage). `[+]` создаёт вкладку; первый вопрос переименовывает её. Переключение вкладок меняет отображаемый чат (состояние сохраняется). Всегда минимум одна вкладка.
- «Подвести итоги»: постоянный чат с фиксированным названием; модель получает TOON-контекст всех остальных чатов (в т.ч. метаданные ответов), follow-up работают.
- Раскладка: вкладки 20% | чат 60% | настройки 20%; на экранах <700px панели перестраиваются.
- Reasoning-модели: рассуждения скрыты под сворачиваемой меткой «Размышление» (`<details>`), свёрнуты по умолчанию, со спиннером во время размышления. Пока модель генерирует ответ, в баббле ассистента показывается **вейтер** (спиннер `.message__waiter`); по завершении (`done`) вейтер убирается и весь текст ответа появляется целиком.
- Настройки генерации (глобальны): «Температура» (`temperature` 0–2), «top_p» (0–1, `0`→`0.01`), «Лимит токенов» (`max_tokens`), «Стоп слова» (`stop` через запятую). Передаются как переопределения на каждый запрос.
- «Режим ответа» (тумблер): выкл — JSON-режим: `response_format={"type":"json_object"}` + системный промпт «Выдавай ответ строго в формате JSON.» (передаётся как `system_prompt` запроса). Рендер JSON-конверта `{thinking, response, date, tokens}`.
- Футер «Сожжено токенов: N» — сумма `prompt+completion` токенов всех запросов за сессию (метаданные из события `done`).
- Блок «вопрос + ответ»: пара «пользователь → ассистент» в `.qa`; строка статистики `.qa__stats`: `время, вход, выход, рассужд., цена` (из серверного `meta`; прочерк при отсутствии).
- Приветственное сообщение «Привет! Чем могу помочь?» при создании чата.
- Отправка: кнопка или `Enter`; `Shift+Enter` — перенос; кнопка блокируется в занятом чате (`chat.busy`). В каждом чате — не более одного запроса; стрим продолжается в фоне при переключении вкладок.
- Поле ввода: авторесайз, максимум 2 строки; при превышении — вертикальный скролл.
- Ошибки — в bubble «Ошибка: …»; пустой ответ — «(пустой ответ)»; при `finish_reason=length` — «<LLM уперлась в ограничение по токенам: N>».

### 5.4. Команды и автокомплит

- При вводе «/» в поле ввода над ним показывается дропдаун команд (фильтрация по префиксу; на текущий момент одна команда).
- `Tab`/`Enter`/клик по пункту — вставка команды **в начало строки** поля ввода + пробел. `↑`/`↓` — навигация, `Esc` — закрыть.
- Список команд: `COMMANDS` в `app.js`.

### 5.5. Команда `/optimize-prompt`

- Ввод `{content}` в виде `/optimize-prompt USER_TEXT` при отправке создаёт **изолированный временный чат** (`kind=ephemeral`):
  - модель — выбранная в текущем чате;
  - настройки — `temperature: 0.1`, `top_p: 0.01`;
  - системный промпт — «Действуй как профессиональный промт-инженер. Создай детальный промт для языковой модели по запросу: USER_TEXT. Промпт должен быть на языке запроса, лаконичен и структурирован.» (USER_TEXT — текст после команды);
  - пользовательское сообщение в изолированном чате — `USER_TEXT`.
- Результат выводится в **модальном окне**: стрим ответа, строка статистики, кнопка «Копировать» (буфер обмена) и «Закрыть». Закрытие также по клику вне окна и по `Esc`.
- При закрытии модального окна временная сессия удаляется и с сервера (`DELETE /api/sessions/{id}`), и из клиента. Незавершённый стрим прерывается (`AbortController`).
- Если после команды нет текста — локальная подсказка без обращения к API. Исходный чат при этом не изменяется.

### 5.6. Консольное логирование

Браузер логирует в консоль (DevTools) весь обмен с сервером:

- `[клиент→сервер] …` — исходящие запросы (POST/DELETE, тела);
- `[клиент←сервер] …` — входящие события (SSE-чанки, статусы).

Управляется флагом `CLIENT_LOG_ENABLED` в начале `app.js`.

## 6. Конфигурация (`.env`)

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `DEEPSEEK_API_KEY` | нет* | — | Ключ DeepSeek API (только на сервере) |
| `OPENCODE_API_KEY` | нет* | — | Ключ подписки OpenCode Go (только на сервере) |
| `PORT` | нет | `3000` | Порт HTTP-сервера |
| `SESSION_TTL_HOURS` | нет | `12` | Период автоочистки неактивных сессий |

`*` — достаточно задать хотя бы один из API-ключей; подключённый ключ активирует соответствующий провайдер.

Загрузка — через pydantic-settings (файл `.env`). Пример — в `.env.example`.

## 7. Требования

- Python **3.10+** (проверено на 3.14).
- Зависимости: `fastapi`, `uvicorn[standard]`, `httpx`, `pydantic-settings`, `toon-format==0.9.0b1` (см. `requirements.txt`).
- Тесты: `pytest`, `pytest-asyncio` (см. `requirements-dev.txt`).

## 8. Безопасность

- API-ключи хранятся только на сервере (из env), в браузер не отдаются.
- `.env` в `.gitignore` (в репозиторий не попадает).
- Статика раздаётся через FastAPI StaticFiles (без path traversal).
- Валидация тел запросов — pydantic; лимит длины `content` ≥ 1.
