# Помогатор2К (ai-challenge)

Простое чат-приложение для общения с [DeepSeek API](https://api-docs.deepseek.com/). Клиент — статическая HTML-страница (JS + CSS), сервер — Node.js, который проксирует запросы к DeepSeek и не раскрывает API-ключ в браузере.

## Возможности

- Чат с выбранной моделью DeepSeek (дропдаун в шапке, список моделей — из API)
- Потоковый вывод ответов (SSE, текст появляется постепенно); у reasoning-моделей рассуждения — под сворачиваемой меткой «Размышление»
- Счётчики израсходованных токенов: общий за сессию + по каждому сообщению
- Настройки генерации: чёткость (temperature), разнообразие (top_p), лимит токенов, стоп-слова, JSON-режим ответа
- API-ключ хранится только на сервере
- Без сторонних зависимостей — используется встроенный `http` и `fetch` из Node.js

## Требования

- Node.js 20.6+ (нужна поддержка `--env-file`), рекомендуется 22+

## Установка

```bash
git clone https://github.com/vitchuk/ai-challenge.git
cd ai-challenge
```

Создайте файл `.env` на основе примера и укажите ваш API-ключ:

```bash
cp .env.example .env   # Windows: copy .env.example .env
```

Откройте `.env` и вставьте ключ:

```
DEEPSEEK_API_KEY=sk-xxxxxxxxxxxxxxxx
PORT=3000
```

## Запуск

```bash
npm start
```

Откройте в браузере: <http://localhost:3000>

## Как это работает

1. Клиент отправляет `{ messages: [...] }` на `POST /api/chat`.
2. Сервер добавляет API-ключ и вызывает `https://api.deepseek.com/chat/completions` с `stream: true`.
3. Ответы DeepSeek (SSE) пересылаются клиенту, который парсит чанки и постепенно выводит текст.

## Настройка порта

По умолчанию используется порт `3000`. Чтобы изменить, задайте `PORT` в `.env` или переменной окружения.

## Воспроизводимость ответов

Полного детерминизма DeepSeek API не гарантирует даже при минимальных настройках. Это не баг приложения — запрос при одинаковых настройках и истории формируется байт-в-байт одинаково.

Почему ответы различаются при «Четкость ответа» = 0 и «Разнообразие ответов» = 1%:

- `temperature=0` — жадный выбор токена, но модель DeepSeek — Mixture-of-Experts: маршрутизация по экспертам, параллелизм GPU (порядок суммирования чисел с плавающей точкой меняется от запуска к запуску) и серверный батчинг дают микроразличия в логитах, из-за которых на «границе» может выигрывать другой токен.
- Reasoning-модели усиливают расхождение лавинообразно: малейшая разница в начале цепочки рассуждений меняет весь дальнейший вывод.
- `top_p` при `temperature=0` практически не влияет на результат (жадный выбор и так берёт топ-токен).
- Параметр `seed` API принимает, но воспроизводимость не гарантирует (проверено тестами).
- Повторный вопрос в том же чате идёт с уже выросшей историей `messages` — промпт другой, поэтому ответ закономерно отличается.

Чтобы получать максимально похожие ответы:

- поставьте «Четкость ответа» = 0;
- используйте модель `deepseek-chat` (не reasoning-модели);
- сравнивайте ответы в свежей сессии (перезагрузка страницы), а не повторяя вопрос в начатом чате;
- формулируйте детерминированные промпты («Ответь ровно: …») — такие ответы воспроизводятся стабильно.
